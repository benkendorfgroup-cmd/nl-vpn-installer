# NL — установка 3x-ui на Debian 12/13

Этот комплект ты запускаешь сам через SSH. Доступ к серверу, пароли и чужие данные передавать Норе не нужно. В комплекте нет данных твоего действующего VPN.

Короткий порядок запуска — в **START-HERE.md**. Для нового запуска подготовлен `bootstrap.sh`: он скачивает закреплённый установщик с GitHub, проверяет его SHA-256, подготавливает недостающие пакеты и запускает быстрый режим. Команда из [COMMAND.txt](COMMAND.txt) использует закреплённый выпуск `v1.0.1` в `benkendorfgroup-cmd/nl-vpn-installer`.

В быстром режиме адрес VPS определяется по серверной стороне SSH-соединения либо одним запросом к `api.ipify.org`. Порт выбирается из свободных 443 или 8443. Если автоматически определить адрес или выбрать порт нельзя, мастер спросит его. Затем нужны только четыре значения из Proxy-Seller: IP статического прокси, HTTP-порт, логин и пароль. Перед созданием VPN остаётся одно подтверждение `INSTALL`. После успешной серверной проверки появляется ссылка.

Быстрый режим рассчитан на статический прокси, у которого адрес подключения совпадает с выходным IP. Для иного выходного IP, входа по разрешённому IP VPS или прямого выхода используй расширенный мастер `--install`, описанный ниже. Быстрый режим можно запустить локальным файлом: `sudo python3 install.py --quick`.

Загрузчик устанавливает только недостающие `python3`, `curl`, `ca-certificates`, `iproute2` и их необходимые зависимости. Полное обновление ОС не запускается; установке запрещено удалять пакеты. Эти пакеты могут быть установлены **до** подтверждения `INSTALL` — оно относится к созданию самого VPN. Существующие приложения он не перенастраивает.

**ОС: Debian 12/13, amd64 или arm64, с systemd.** Если в панели хостинга доступна только Debian 12, выбирай Debian 12. Обновление ОС до 13 не требуется. Если на сервере уже есть чужие данные, не переустанавливай его ради этого установщика: переустановка их удалит. Скрипт сам ОС не меняет.

Что получится:

- 3x-ui **v3.11.0**, официальный архив с проверкой закреплённого SHA-256;
- подключение **VLESS + REALITY**, название в клиенте — **NL**;
- выбор выхода: обычный IP VPS либо купленный HTTP-прокси с логином и паролем или с уже настроенным у продавца доступом по IP VPS;
- отдельная служба с ограниченными правами; панель доступна только через SSH;
- новые ключи и случайные учётные данные, созданные на целевом сервере.

Версия закреплена намеренно: следующий запуск не скачает неожиданное обновление. Обновлять этот вариант установки нужно отдельно, после проверки новой версии. Системные кнопки установки, обновления и управления файрволом в панели для этой ограниченной службы не предназначены.

## 1. Передать установщик

Распакуй архив на своём компьютере и открой терминал в распакованной папке. На Windows это PowerShell. В следующих командах замени `SSH_USER` на свой SSH-логин, а `SERVER_IP` — на адрес второго VPS. Если SSH использует нестандартный порт, добавь `-P ПОРТ` к `scp` и `-p ПОРТ` к `ssh`.

```powershell
scp .\install.py SSH_USER@SERVER_IP:~/nl-vpn-install.py
ssh SSH_USER@SERVER_IP
```

Это копирует один файл и открывает терминал сервера. Никакой VPN-клиент на Windows не устанавливается.

На сервере нужны Python 3, curl, сертификаты, iproute2, systemd и стандартные средства управления пользователями. На минимальной Debian недостающие пакеты можно поставить самостоятельно:

```sh
sudo apt-get update
sudo apt-get install --no-install-recommends python3 curl ca-certificates iproute2
```

Если вошёл как `root`, в командах не нужно слово `sudo`.

## 2. Сначала проверка

```sh
sudo python3 ~/nl-vpn-install.py --check
```

Проверка не устанавливает ничего, не обращается к внешним сайтам и не читает каталоги чужих приложений. Она смотрит версию ОС, архитектуру, доступную память и место, наличие необходимых команд, занятость нужных портов и отсутствие прежней установки.

Если TCP/443 занят, например сайтом, можно выбрать свободный порт:

```sh
sudo python3 ~/nl-vpn-install.py --check --port 8443
```

При установке мастер спросит порт; укажи тот, который проверял. Можно также передать его через `--port`. Занявшая порт служба не останавливается.

Проверка не является полным аудитом всех служб сервера. Для начала нужно не менее 512 МБ доступной RAM и 750 МБ свободного места; новой службе задан потолок 768 МБ RAM. Общие ресурсы сервера всё равно используются, поэтому после установки проверь и прежние приложения.

## 3. Установить

```sh
sudo python3 ~/nl-vpn-install.py --install
```

Или, если выбрал другой порт:

```sh
sudo python3 ~/nl-vpn-install.py --install --port 8443
```

Установщик спросит:

1. Порт нового VPN: обычно 443. Если занят, предложит выбрать другой, например 8443. При запуске с `--port` этот вопрос пропускается.
2. Публичный IPv4 именно этого VPS — из панели хостинга.
3. Выход через IP VPS или через HTTP-прокси. По умолчанию выбран прокси.
4. Для прокси: адрес и **HTTP-порт** из кабинета продавца.
5. Способ входа в прокси: логин и пароль либо доступ по IP, **уже разрешённый в кабинете продавца**. Во втором случае пароль не запрашивается и не записывается. Кабинет продавца установщик не меняет.
6. Ожидаемый внешний IPv4 — адрес, который должны видеть сайты. По умолчанию предложен адрес прокси, но он может отличаться; при необходимости введи другой.
7. Подтверждение словом `INSTALL`, когда покажет выбранные параметры.

Пароль вводится скрыто; если терминал не умеет скрывать ввод, установка остановится. SSH-логин и SSH-пароль повторно вводить в мастере не нужно. Данные прокси сохраняются в приватной конфигурации на целевом сервере; в ссылку для клиента они не входят. При парольном входе соединение с самим прокси использует его учётные данные.

В режиме прокси нужен **HTTP CONNECT**, как у использованного в нашем эксперименте продукта. SOCKS-порт от продавца вместо HTTP-порта не подойдёт. Для этого варианта используется обычный HTTP-прокси: участок VPS → прокси не имеет собственного TLS, хотя HTTPS сайтов внутри туннеля остаётся зашифрованным. Если продавец предлагает только HTTPS-прокси с TLS, этот установщик пока не подходит.

Нельзя получить произвольный внешний адрес, просто вписав его: он должен принадлежать твоему VPS или быть реально предоставлен выбранным прокси. Существующие ключи и ссылка от другого сервера сюда не копируются.

## 4. Что он проверит сам

После установки скрипт запускает временный **Linux-клиент на самом VPS**, не на твоей Windows:

- проверяет, что новый VLESS/REALITY принимает подключение;
- делает HTTPS-запрос через него и сравнивает выходной IP с указанным;
- проверяет DNS-запрос через VPN и серверный DNS, использующий DoH;
- в режиме прокси запускает отдельную копию правил с недоступным прокси: запрос должен завершиться ошибкой, без прямого выхода;
- проверяет, что панель и служебный API слушают только `127.0.0.1`.

Только после успешных проверок включается автозапуск. При ошибке новая служба останавливается; установщик не переключает её на прямой выход. Собственные файлы остаются для разбора. Повторный запуск поверх них запрещён.

Служебные сетевые обращения ограничены загрузкой архива с GitHub, подключением REALITY к `www.microsoft.com`, запросами к `api.ipify.org`, DNS Cloudflare и проверочным DNS-именем `example.com`. Нагрузочных тестов и постоянного опроса нет.

## 5. Разрешить подключение и получить ссылку

Установщик **не меняет правила существующего файрвола**. Разреши входящий **TCP/443** — либо выбранный TCP/8443 — в панели провайдера и в уже используемом серверном файрволе. Если правила уже разрешают этот порт, добавлять ничего не нужно. Не включай новый файрвол поверх существующего и не сбрасывай правила.

Панель **2053** и внутренний API **62789** наружу открывать не нужно.

После успешных серверных проверок мастер сам покажет новую ссылку. Получить её повторно:

```sh
sudo cat /root/nl-vpn-access/NL.txt
```

Скопируй целиком строку `vless://…` и импортируй в свой клиент, например v2rayN: **Серверы → Импорт из буфера обмена**. Ссылка даёт доступ к VPN, поэтому не публикуй её. Старое подключение продолжает существовать отдельно.

С нового устройства проверь `https://api.ipify.org` с включённым профилем: должен отображаться выбранный выходной IP. Серверная проверка выше не проверяет внешний файрвол и маршрут от твоего компьютера.

## 6. Открыть панель

```sh
sudo cat /root/nl-vpn-access/panel.txt
```

Там будут адрес панели, логин, пароль и готовая команда SSH-туннеля. Выполни эту команду в **новом окне PowerShell на своём компьютере**, подставив свой SSH-логин. Пока окно открыто, локальный адрес панели доступен в браузере. HTTP до localhost защищён SSH на участке между компьютером и сервером.

Пароль можно перенести в свой менеджер паролей. Не меняй адрес прослушивания панели с `127.0.0.1` на публичный.

### Защита панели после первого входа

В установщик уже заложены закрытая от прямого доступа из интернета панель, случайные логин и пароль, случайный путь панели, ограниченная учётная запись службы и приватные файлы с доступами. Закрытое подключение к панели защищается SSH. Сам по себе случайный адрес страницы не заменяет пароль.

Остались два персональных шага, которые установщик автоматически не выполняет:

1. **SSH-ключ.** Настрой вход со своего компьютера по ключу, защищённому парольной фразой. Проверь вход в отдельном новом окне, сохранив старое SSH-соединение и доступ к консоли провайдера. Если сервером пользуется другой человек, учти и его доступ. Только после этого можно отдельно отключать парольный вход по SSH; этот установщик настройки SSH не меняет.
2. **Двухфакторная защита 3x-ui.** После входа открой настройки панели и раздел двухфакторной аутентификации / 2FA. Добавь показанный QR-код или секрет в своё приложение-аутентификатор, сохрани секрет для восстановления отдельно и заверши включение по интерфейсу панели. Затем проверь новый вход с паролем и одноразовым кодом. Если меняешь пароль панели, сначала смени его, затем настрой 2FA: в этой версии обновление учётных данных через панель может сбросить настройку 2FA.

Итоговый порядок входа: SSH по ключу → локальный адрес панели → пароль панели + код из аутентификатора. Для обычного пользования VPN открывать панель каждый раз не нужно.

3x-ui и Debian также требуют своевременных обновлений безопасности. Версия в комплекте закреплена для воспроизводимости, а не для бессрочной работы без обновлений. Перед заменой версии сохрани приватную резервную копию конфигурации и проверь совместимость; встроенная кнопка обновления панели в этом варианте установки не используется.

Поддержка 2FA и поведение при смене учётных данных проверены по [исходному коду установленной версии](https://github.com/MHSanaei/3x-ui/blob/v3.11.0/internal/web/service/panel/user.go).

## Где расположены файлы и как остановить

| Путь | Содержимое |
|---|---|
| `/opt/nl-vpn` | Файл панели |
| `/var/lib/nl-vpn` | Новая база панели, Xray и его конфигурация |
| `/var/log/nl-vpn` | Приватные журналы; могут содержать секреты |
| `/root/nl-vpn-access` | Доступы, ссылка и результат проверки |
| `/etc/systemd/system/nl-vpn.service` | Отдельная служба |

Статус:

```sh
sudo systemctl status nl-vpn --no-pager
sudo cat /root/nl-vpn-access/result.json
```

Остановить и убрать из автозапуска, сохранив файлы:

```sh
sudo systemctl disable --now nl-vpn
```

Скрипт не изменяет SSH, системный DNS, настройки сети или службы других приложений. Он добавляет системную учётную запись `nl-vpn` и свою systemd-службу. Это не официальный универсальный установщик 3x-ui: расширения, которым нужны root-права, здесь намеренно не включены. Смена маршрутов в панели может изменить гарантии исходной конфигурации; созданные позже подключения без собственного правила маршрутизации будут блокироваться.

## Границы проверки

- **На момент подготовки комплект проверен локальными автоматическими тестами. Полная установка на Debian 12/13 ещё не была выполнена.** Первая реальная установка должна считаться проверочной; это не обещание безошибочной работы на произвольном сервере.
- В режиме HTTP-прокси обычный UDP блокируется; DNS направляется через DoH. Звонки и игры с обязательным UDP могут не работать. HTTPS использует TCP.
- Отсутствие прямого выхода при отказе прокси относится к трафику этого VPN на сервере. Остальные процессы VPS не переводятся автоматически на прокси.
- Защита от утечки при выключении клиента на компьютере — отдельная настройка клиента/Windows. Этот установщик не создаёт системный kill switch на компьютере и не проверяет WebRTC или DNS браузера.
- В режиме выхода через VPS купленный прокси вообще не используется.
- Геолокация в сторонних базах, репутация IP и решения сервисов об аккаунтах не определяются установщиком.
- Claude Code, WARP, Amnezia и другие приложения этим комплектом не устанавливаются.
